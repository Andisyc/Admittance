### 已确认的边界与决策

- 本会话开发工作区：`/Users/sss9999/enbodied_intelligence/ADAPT/Admittance`；此前协作者工作区为 `/Users/chengyuxuan/ArtiIntComVis/Admittance`。仓库包含 UniLab 源码，`pyproject.toml` 的包名仍为 `unilab`；按此现状推进，不把上一轮“独立扩展包”建议当作已确认架构。
- 基础设施采用 UniLab；Encoder–Decoder、动作先验训练和潜空间微调参考 [hazel-hammer/Anybody](https://github.com/hazel-hammer/Anybody)。前次源码调查参考提交：`0cffa139eab0bc145c9216223e249f03c67a324c`，迁移时需核对并固定来源。
- AMASS 用于机器人动作重定向后、物理仿真中的策略训练，不是仅在关节轨迹上离线拟合 Autoencoder。**2026-10-17 用户明确选择直接 RL 更新 Encoder–Decoder，不采用 Teacher 蒸馏。**潜码是确定性归一化输出，Gaussian 探索在原始关节动作上；冻结 Decoder 的后续潜空间 RL 属于后续阶段。
- 必须复用 UniLab 的异构采集与学习设备分离、异步数据传输及权重同步能力；不能以搬入 Anybody 的同步训练器替代该目标。性能是否保留必须由同硬件、同配置的实测判断。
- 后续研究意图：无额外施加外力时，以全身 `q_default` 为标称姿态偏好，按速度命令运动；持续外力下允许全身协同适应。动作先验不意味着部署时必须输入参考动作序列，也不自动保证所有潜码均自然或稳定。
- 后续外力残差计划采用 ADAPT 的观测器；Locomotion Encoder 与 Torque Encoder 的分阶段训练、潜码修正属于研究背景，不在本次文档初始化中实施或定型。
- 最新授权为训练实现内置于 `src/unilab/rl`，移除外部 `unilab-rl` 运行依赖；保留可 pickle 的 EnvFactory 注入和采集/学习分离。物理后端仍为 unisim；本次不借迁移改变仿真时序或伪造历史传感器能力。CI 通过后再合并 main，不跳过检查；不在本地下载训练数据或训练，S4 实施和远程运行仍按各自范围推进。

### 模块职责与预期链路

| 模块 | 职责与边界 |
| --- | --- |
| AMASS 数据管线 | 人体动作读取、目标机器人重定向、UniLab 动作格式适配；明确关节/刚体顺序、坐标系、四元数约定、采样频率及数据来源。 |
| 仿真动作训练 | 在 UniLab 动作跟踪任务中直接 RL 更新 Encoder–Decoder；沿用仓内 APPO/V-trace、环形传输及权重同步，无 Teacher 监督。 |
| Encoder–Decoder | 参考 Anybody 学习潜空间动作先验；明确 Encoder 输入和 Decoder 的潜码、本体感知及动作输出语义，保存独立可加载的模型。 |
| 异构异步训练 | 仓内 `unilab.rl` 负责采集、传输、更新、权重同步和恢复；需要潜空间 RL 时，区分训练用潜变量动作与仿真用关节动作。 |
| 评估与导出 | 验证跟踪与下游使用、模型加载和恢复、推理路径及吞吐；不将网络前向测试等同于策略质量或真机证据。 |

当前正式路线：预重定向 G1 AMASS → 名称映射/姿态一致性检查 → 本仓 G1 50 Hz FK/NPZ → MUSE 524 维观测 → APPO 直接更新 E/D。原始 AMASS → 显式匹配 SMPL-H/DMPL → 命名姿态/GMR 的入口继续保留，缺权重不再阻塞预重定向路线。初始 profile 目标全可见、无归一化/编译，Critic 为独立 MLP；默认 G1 任务未替换。后续动作先验质量与冻结 Decoder 的下游训练另行验收。
