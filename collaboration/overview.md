# Admittance 协作任务总览

**当前状态：**`feat/anybody-muse-s2` 已完成 S1 接口核查、S2 纯网络及 S3 原始 AMASS 数据层，当前为 **S3 完成、S4 尚未开始**。`main@b1e0c1c6` 已通过 `514ed643` 合入并推送；仿真/异步训练链路尚未接通，没有开始训练。本文件是唯一协作状态入口，技术接口与已有验证保留在 [Anybody 接入记录](../note/anybody/task_canvas.md)，后续会话同时阅读最新交接，不能把静态网络和数据测试当作训练闭环。

### 已确认的边界与决策

- 后续开发工作区：`/Users/chengyuxuan/ArtiIntComVis/Admittance`。当前目录已包含 UniLab 源码，`pyproject.toml` 的包名仍为 `unilab`；按此现状推进，不把上一轮“独立扩展包”建议当作已确认架构。
- 基础设施采用 UniLab；Encoder–Decoder、动作先验训练和潜空间微调参考 [hazel-hammer/Anybody](https://github.com/hazel-hammer/Anybody)。前次源码调查参考提交：`0cffa139eab0bc145c9216223e249f03c67a324c`，迁移时需核对并固定来源。
- AMASS 用于机器人动作重定向后、物理仿真中的策略训练，不是仅在关节轨迹上离线拟合 Autoencoder。采用 Teacher 后蒸馏还是其他具体训练组织，需在实现前依据代码确认。
- 必须复用 UniLab 的异构采集与学习设备分离、异步数据传输及权重同步能力；不能以搬入 Anybody 的同步训练器替代该目标。性能是否保留必须由同硬件、同配置的实测判断。
- 后续研究意图：无额外施加外力时，以全身 `q_default` 为标称姿态偏好，按速度命令运动；持续外力下允许全身协同适应。动作先验不意味着部署时必须输入参考动作序列，也不自动保证所有潜码均自然或稳定。
- 后续外力残差计划采用 ADAPT 的观测器；Locomotion Encoder 与 Torque Encoder 的分阶段训练、潜码修正属于研究背景，不在本次文档初始化中实施或定型。
- 最新授权为评估失败、修复确定的问题并合并当前 PR 到 main；未明确豁免失败检查或授权改写外部训练/仿真接口。不在本地下载训练数据或训练；S4 实施和远程运行仍按各自范围推进。

### 模块职责与预期链路

| 模块 | 职责与边界 |
| --- | --- |
| AMASS 数据管线 | 人体动作读取、目标机器人重定向、UniLab 动作格式适配；明确关节/刚体顺序、坐标系、四元数约定、采样频率及数据来源。 |
| 仿真动作训练 | 在 UniLab 的动作跟踪环境中学习可执行动作能力；需要 Teacher 时，提供可供蒸馏的策略与观测接口。 |
| Encoder–Decoder | 参考 Anybody 学习潜空间动作先验；明确 Encoder 输入和 Decoder 的潜码、本体感知及动作输出语义，保存独立可加载的模型。 |
| 异构异步训练 | 复用 UniLab/uni-rl 的采集、传输、更新、权重同步和恢复流程；需要潜空间 RL 时，区分训练用潜变量动作与仿真用关节动作。 |
| 评估与导出 | 验证跟踪与下游使用、模型加载和恢复、推理路径及吞吐；不将网络前向测试等同于策略质量或真机证据。 |

预期链路：AMASS → 机器人参考动作 → UniLab 仿真动作训练 → Encoder–Decoder 动作先验 → 冻结 Decoder 的下游训练。具体接口尚未冻结。
