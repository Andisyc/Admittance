# Admittance 协作任务总览

## Overall design（整体设计）

**当前目标：**在 Admittance 仓库中，将 Anybody 的 Encoder–Decoder 动作先验及基于 AMASS 的仿真训练流程完整整合进 UniLab，并接入 UniLab 的高速异构、异步训练架构，形成可训练、可评估、可恢复的完整链路。

**当前状态：**S1–S3 与训练代码内置已通过 PR #1 合入 `main@424d8ddf`；文档发布修复通过 PR #2 合入 `main@f743b965`。**S4 数据转换与 Encoder–Decoder 直接 RL 接线代码已实现，284 项非训练检查通过；按用户要求停在第三步（远端短训练验收）之前**。真实 AMASS 人体重建仍缺匹配权重，尚无实际采样/参数更新或策略效果证据。本文件是唯一协作状态入口，旧接口与历史验证保留在 [Anybody 接入记录](../note/anybody/task_canvas.md)，当前方案见 [ADR-0009](../docs/sphinx/source/adr/ADR-0009-anybody-direct-rl.md) 及最新交接；不能把局部验证当作机器人训练闭环。

**训练内置交付：**用户最新要求已按 [ADR-0008](../docs/sphinx/source/adr/ADR-0008-in-tree-training-runtime.md) 实现并推送：通用训练、AMP、蒸馏和 IPC 位于 `src/unilab/rl`，不再依赖外部训练发行包。实现提交 `93e4f56f`，另补齐已有 G1WalkHeight 的迁移矩阵登记。实现/验证范围见最新交接；**当前头、最新 CI 和 main 合并结果以 [PR #1](https://github.com/Andisyc/Admittance/pull/1) 实时状态为准**，历史交接不替代 GitHub 当前结果。门禁仍为最终头 CI 全通过后普通合并。

### 已确认的边界与决策

- 本会话开发工作区：`/Users/sss9999/enbodied_intelligence/ADAPT/Admittance`；此前协作者工作区为 `/Users/chengyuxuan/ArtiIntComVis/Admittance`。仓库包含 UniLab 源码，`pyproject.toml` 的包名仍为 `unilab`；按此现状推进，不把上一轮“独立扩展包”建议当作已确认架构。
- 基础设施采用 UniLab；Encoder–Decoder、动作先验训练和潜空间微调参考 [hazel-hammer/Anybody](https://github.com/hazel-hammer/Anybody)。前次源码调查参考提交：`0cffa139eab0bc145c9216223e249f03c67a324c`，迁移时需核对并固定来源。
- AMASS 用于机器人动作重定向后、物理仿真中的策略训练，不是仅在关节轨迹上离线拟合 Autoencoder。**2026-10-17 用户明确选择直接 RL 更新 Encoder–Decoder，不采用 Teacher 蒸馏。**潜码是确定性归一化输出，Gaussian 探索在原始关节动作上；冻结 Decoder 的后续潜空间 RL 属于后续阶段。
- 必须复用 UniLab 的异构采集与学习设备分离、异步数据传输及权重同步能力；不能以搬入 Anybody 的同步训练器替代该目标。性能是否保留必须由同硬件、同配置的实测判断。
- 后续研究意图：无额外施加外力时，以全身 `q_default` 为标称姿态偏好，按速度命令运动；持续外力下允许全身协同适应。动作先验不意味着部署时必须输入参考动作序列，也不自动保证所有潜码均自然或稳定。
- 后续外力残差计划采用 ADAPT 的观测器；Locomotion Encoder 与 Torque Encoder 的分阶段训练、潜码修正属于研究背景，不在本次文档初始化中实施或定型。
- 最新授权为训练实现内置于 `src/unilab/rl`，移除外部 `unilab-rl` 运行依赖；保留可 pickle 的 EnvFactory 注入和采集/学习分离。物理后端仍为 unisim；本次不借迁移改变仿真时序或伪造历史传感器能力。CI 通过后再合并 main，不跳过检查；不在本地下载训练数据或训练，S4 实施和远程运行仍按各自范围推进。
- 2026-10-16 用户另行授权在 Mac 尝试单段转换验证：允许独立环境、官方机器人资源及一段真实动作；这仅放开本地验证，不扩展为批量训练数据下载或本地训练。样本/依赖留在忽略目录，用户确认没有人体模型权重；仍需匹配模型与权重才能继续真实重定向。
- 用户随后明确由助手选择本地验证方案。已选官方 LAFAN1 BVH 骨架动作，直接验证公共命名姿态边界之后的链路，无需 SMPL 权重；这是局部可行性验证，不把正式 AMASS 训练源替换为 LAFAN1，也不宣称 AMASS 人体重建已通过。
- 当前授权是推进数据转换与训练接线，**停在远端短训练验收前**；允许非训练契约/梯度连通性/FK/权重传输检查，不执行 optimizer 更新、环境 rollout 或训练。用户要求提交后，实现已以 `01f413ec` 推送至 [Andisyc/Admittance 的 feat/anybody-muse-s2 分支](https://github.com/Andisyc/Admittance/tree/feat/anybody-muse-s2)；本轮未合并 main。此前交接中的“未提交/未推送”仅描述当时状态。

### 模块职责与预期链路

| 模块 | 职责与边界 |
| --- | --- |
| AMASS 数据管线 | 人体动作读取、目标机器人重定向、UniLab 动作格式适配；明确关节/刚体顺序、坐标系、四元数约定、采样频率及数据来源。 |
| 仿真动作训练 | 在 UniLab 动作跟踪任务中直接 RL 更新 Encoder–Decoder；沿用仓内 APPO/V-trace、环形传输及权重同步，无 Teacher 监督。 |
| Encoder–Decoder | 参考 Anybody 学习潜空间动作先验；明确 Encoder 输入和 Decoder 的潜码、本体感知及动作输出语义，保存独立可加载的模型。 |
| 异构异步训练 | 仓内 `unilab.rl` 负责采集、传输、更新、权重同步和恢复；需要潜空间 RL 时，区分训练用潜变量动作与仿真用关节动作。 |
| 评估与导出 | 验证跟踪与下游使用、模型加载和恢复、推理路径及吞吐；不将网络前向测试等同于策略质量或真机证据。 |

当前路线：AMASS → 显式匹配的 SMPL-H/DMPL 人体重建 → 命名姿态/GMR → 本仓 G1 FK/NPZ → MUSE 524 维观测 → APPO 直接更新 E/D。初始 profile 目标全可见、无归一化/编译，Critic 为独立 MLP；默认 G1 任务未替换。后续动作先验质量与冻结 Decoder 的下游训练另行验收。
