## 运行结果与证据边界

1. 实际导入 GMR，加载模型并构造两组各 14 个 IK task 成功；GMR nq/nv/nbody 为 36/35/39，本仓模型为 36/35/31。DAQP 与 ProxQP 均可用，实际测试调用 DAQP。
2. 以 seed=20261016，在 GMR 限位内部生成 16 组姿态，包含非单位根旋转；按相同关节名/顺序送入两个真实 MuJoCo 模型，分别 `mj_forward`。共同 30 个命名刚体的位置、旋转矩阵最大绝对误差均为 0。此为数值 FK 证据，不是动力学/接触可行性证明。
3. 从已知机器人姿态反推一份命名目标，只用于触发 GMR 的缩放/offset/真实 `retarget()` 求解路径。误差由 0.9178132541 降至 3.410824542e-7，返回有限的 36 维 qpos。**该输入来自机器人自身，不是人体捕捉；不得当作 AMASS 转换成功。**
4. 本仓真实 AMASS reader 读取上述样本通过：2610 帧、120 Hz、male、poses[2610,156]、betas[16]、dmpls[2610,8]。字段没有模型声明，model_type 保持 unknown；没有补零、截断或强行指定为 SMPL-X。
5. 通过正常包入口实例化本仓 `MotionLoader`，成功读取已有 `walk_forward_loop_002__A022.npz`：455 帧、29 关节、50 Hz、body 轴为 30。此为已有文件的读取证明，**不是本次 AMASS 导出**，也没有证明该旧产物与当前 nbody=31 的模型 body-id 对齐；不得用它替代新导出的索引验收。
6. 真实人体重建与重定向未执行：用户无匹配人体权重、源文件模型声明 unknown；没有生成 G1 NPZ 或播放真实转换动作。官方 AMASS 下载入口实际跳转登录页，不能从未登录网页直接取得所需配套模型。

另发现源码级依赖风险：此固定 GMR 将 `self.ik_limits` 作为 `mink.solve_ik` 第六个位置参数；Mink 1.3.0 第六参为 safety_break，第七参才是 limits。当前探针未启用 velocity limit，默认 ConfigurationLimit 仍由 Mink 使用，所以通过不证明显式限位列表/速度限位已传递。没有在本轮改外部源码；生产接入前必须用显式关键字适配或核实兼容版本，并验证约束，不能从本次成功推断全部 API 兼容。
